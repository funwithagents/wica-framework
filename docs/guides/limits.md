# What v1 does not do yet

The limits to design around. Each is a decision recorded in a spec, with the design that will lift it where one exists; none is an accident.

- **One reasoning step at a time.** A trigger arriving while a step is in flight is **dropped, not queued**: its value is in the World for the next step to see, but nothing wakes the Agent for it. `wica.on_agent_trigger_dropped` reports each one. Coalescing only batches the burst *before* a step starts. Concurrent reactions, a queued follow-up step and a model-issued `cancel_reaction` are designed and deferred ([specs/agent.md](../../specs/agent.md), "Concurrency and long-running Commands in v1").
- **The reply is complete text.** The output sink receives the model's whole text once per step; there is no token streaming. Broader output modalities are Commands, and a cancellable utterance is the output Command ([commands.md](commands.md#the-output-command)).
- **History is the Agent's only memory, and bounding it is lossy.** With `history_reactions` or `history_budget` set, anything older than the bound is gone for the model: an earlier instruction, a name, its own replies. State that must outlive the bound belongs in a World entry. The budget reads the previous call's usage, so it lags one step: keep the fraction well below 1, and keep a `history_reactions` cap as the backstop ([../reference/configuration.md](../reference/configuration.md#history-bounds)).
- **The World is a snapshot, not a log.** It holds the current and the previous version of each entry. The Agent keeps the history as re-renderable snapshots of what it observed.
- **Cancellation reaches the task, not always the work.** A sync Command runs in a thread that cannot be interrupted: on cancel its entry reads `cancelled` while the function runs to completion in the background. Prefer `async`, or make a long sync Command cooperative ([commands.md](commands.md#cancellation-reaches-the-task-not-always-the-work)).
- **A response's Commands all run at once.** WICA neither serializes them nor asks the provider for one call per response; a shared resource is yours to guard, and the primer asks the model to sequence dependent actions across steps ([commands.md](commands.md#what-happens-when-the-model-calls-one)).
- **The runtime primer cannot be turned off or edited.** WICA appends it to your system prompt; whether an application can customize it is an open question ([specs/agent.md](../../specs/agent.md), "System prompt composition").
- **Names and keys are constrained.** Command names are unique, `noop` and `cancel_command` are reserved; World keys are non-empty, without whitespace or `" < > &`; `agent:` is the framework's prefix ([../reference/api.md](../reference/api.md#contracts)).
- **Do not stop the Wica from inside its own loop.** `stop()` and `close()` called from a sink, a Command or an Event subscriber raise `RuntimeError`; hand the call to another thread.
- **Distributed through git, not PyPI, at version 0.1.** The API changes between commits without a deprecation period: pin a commit. No provider is bundled; install an extra.
