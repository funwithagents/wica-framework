# Outputs reported as fields: the tooling stops inferring

**Status:** Done

Implements the reporting additions of [specs/instrumentation.md](../specs/instrumentation.md) (`CommandTrace.is_output` and `triggers_step`, the broader `noop`) and [specs/agent.md](../specs/agent.md) (`CommandIssued.is_output`, `on_command_started`, the `noop` rule), surfaced on the facade ([specs/wica.md](../specs/wica.md)), and moves the test tooling, the benchmark measures and the Gradio panels onto them ([specs/wica-tester.md](../specs/wica-tester.md), [specs/benchmark.md](../specs/benchmark.md), [specs/gradio-contrib.md](../specs/gradio-contrib.md)).

**Why.** After the text output ([202611171200_text-output.md](202611171200_text-output.md)), the checks, the harness and the panels still reproduced decisions the Agent makes: an output was recognised by its name, the first output of a reaction by its position in `command_call_ids`, whether an output's end wakes a step by querying `Agent.output_wakes` at the right moment, and an output's start by reading a World entry's previous version. A consumer should read documented fields and Events, so a change in how the Agent implements outputs does not ripple into it. Three detection gaps found on the way are fixed with it:

- **A decline with private text** (`reasoning… <noop/>`) did not set `noop`, so `no_noop_on_input` and the noop measures missed it (2 of 50 declines in recent live runs, Haiku).
- **An empty response** — a decline, per the spec — failed `no_failed_reactions`.
- **Two tags in one reply** counted as an extra utterance in `extra_output`.

## Scope

1. **Core.**
   - `CommandIssued.is_output`.
   - `CommandTrace.is_output` and `triggers_step`.
   - `Agent.on_command_started`, surfaced as `wica.on_agent_command_started`: every Command's start (a tool call at dispatch, an output at its first words), so the Event already fits a streaming tool call.
   - The `noop` rule: no output delivered and no tool call.
   - `Agent.output_wakes` removed.
2. **Tooling** (`wica.testing`).
   - The Probe recognises outputs by `is_output` and follows every Command from `on_command_started`, with no backfill.
   - `"idle"` reads `triggers_step`.
   - `no_failed_reactions` does not count `empty`.
   - `extra_output` counts responses, not tags.
   - `answer_latency` ends at the answering output's own `CommandTrace.started_at`.
3. **Gradio contrib.** The transcript opens every Command's item on `on_command_started`.
4. **Specs.** `wica-tester.md`, `benchmark.md` and `gradio-contrib.md` updated for the above, including `cancels_when_asked`'s meaning: it confirms the speech stopped, which any new output now does.
5. **Docs.** The API reference (`output_wakes` out; the new fields and Event in), the latency guide, the testing guide.

## Tests

- **Core.**
  - `is_output` is set on outputs only, on both Events.
  - `triggers_step`:
    - a Command with and without `triggers_on_completion`;
    - an output with a granted note, with no note, and past the cap;
    - a cancelled one of each.
  - `on_command_started` fires before the `running` value, for a tool call and an output, so a listener attached in it sees the whole life; for each `call_id`, started then issued then ended.
  - `noop`: `<noop/>`, private text and `<noop/>`, empty, private text with no output Command; not set when an output or a tool call happened.
- **Tooling.**
  - Idle with and without a granted wake, driven by `triggers_step` alone.
  - The Probe follows an output from its start.
  - `no_failed_reactions` passes an empty response.
  - `extra_output` is 0 for one reply in two tags and 1 for two replies.
  - `no_noop_on_input` catches a decline with private text.
- **Live.** The gate on every provider with a key, once; the detection changes move no step on their own.
