# The output Command as a tool call, as an option

**Status:** Done

Implements "The output Command as a tool call" and the `set_output_command(…, as_tool, force)` wiring of [specs/agent.md](../specs/agent.md), with the `output_command_required` guard back in tool mode; the Commands and facade specs follow ([specs/commands.md](../specs/commands.md), [specs/wica.md](../specs/wica.md)), and the test robot gains a switch to run the live gate in tool mode ([specs/testing.md](../specs/testing.md)).

**Why.** Tag output ([202611171200_text-output.md](202611171200_text-output.md)) made the forced tool call disappear. Some models were better with it: ministral-14b called its actions instead of describing them (47 of 48 live gate tests over three runs, against 37 with tags), and gpt-4o and gpt-4o-mini stayed silent on background sounds more often. Others were worse, local servers above all. The application should choose per model, so the tool-call output comes back as an option of `set_output_command`, without displacing tag mode as the default.

## Decisions

1. **Waking.** The end of every spoken output wakes a step, ended by a `noop` call, as before; the chain is bounded by `max_next_steps`. A cancelled output wakes nothing.
2. **Forcing goes with the mode.** `as_tool=True` forces a tool call by default; `force=False` leaves it unforced (Anthropic extended thinking, a server that rejects `tool_choice`). `AgentConfig.force_tool_call` does not come back.
3. **The switch is a boolean**, `as_tool`, on `set_output_command`.

## Scope

1. **Agent** (`src/wica/agent.py`).
   - `set_output_command(fn, *, as_tool=False, force=True)`: in tool mode, build the output tool from the signature (`text`, then the attributes, `Literal` as enum, defaults) and bind it with a `noop` tool; rebind on a mode change.
   - The forced binding back (`tool_choice="any"`, the Hub's `required` path).
   - The tool-mode primer clauses (speak only by calling the output Command, free text is private, calling it again replaces what is being said; call `noop` to do nothing).
   - Dispatch: an output tool call opens an output with the whole text; a `noop` call sets the record's flag; both recorded as native tool calls (`noop` with a plain acknowledgement).
   - Waking under `max_next_steps`; the World entry in the call form; the barge-in cut rewriting the recorded `text`.
   - `agent.commands` unchanged: the output tool and `noop` are bound but not listed.
2. **Guards** (`src/wica/guards.py`). `ModelResponse.output_command_name`; `output_command_required` back among the defaults, active only when it is set; `incomplete_response`'s "cut before the call the output Command requires" case back.
3. **Facade** (`src/wica/wica.py`): the two keyword arguments.
4. **Test robot** (`tests-e2e/robot_app.py`): `WICA_ROBOT_OUTPUT=tool`.
5. **Docs**: the API reference (the signature, the guard), the Commands guide (when to choose which mode), the local-models guide (tool mode needs `tool_choice`).
6. **Live coverage by output mode** ([specs/testing.md](../specs/testing.md) "E2e configs", [specs/ci.md](../specs/ci.md)). An e2e config becomes a test config: its `agent` block (a `WicaConfig`'s) beside a required `output` (`tag` or `tool`), loaded strictly by `support.load_e2e_config`; `WICA_ROBOT_OUTPUT` becomes a by-hand override of every config's mode. Mistral runs in tool mode, the Hub's model in both (a sixth config, `e2e.huggingface-hub-tool.config.json`, and a sixth `live` job); Mistral's three tag-mode `KNOWN_FLAKY` entries go, and the two tool-mode configs get theirs by the three-runs rule. `tests-e2e/test_e2e_configs_fake.py` (key-less) pins the loader and every committed config.

## Tests

- Tool mode, scripted model:
  - an output tool call is delivered with its attributes, whole text, to an `OutputStream` or a `str` output Command;
  - a `noop` call sets the flag and issues nothing;
  - the binding is forced, and unforced with `force=False`;
  - the tools bound are the application's, `cancel_command`, the output tool and `noop`, while `agent.commands` lists neither of the last two;
  - waking after each output, under the cap;
  - a cancelled output does not wake;
  - one voice across responses;
  - history renders native calls with valid tool results;
  - the cut rewrites the recorded text;
  - a plain-text response is rejected by `output_command_required` and retried;
  - switching modes rebinds and recomposes the prompt.
- Tag mode untouched: the existing suite passes unchanged.
- Guards: `output_command_required` with and without an output tool.
- Live: the gate in tool mode on every provider with a key, and once in tag mode.

## Result

Lint, format and types clean; the fast tier (704 passed) and the key-less e2e set (22 passed), and CI on the pull request on every platform. Tag mode is unchanged: its composed prompt is byte-identical to `main`'s, and the existing suite passes as it was, apart from the guard list gaining `output_command_required`.

- **Live set in tag mode**, dispatched on the branch (CI run 44162675650): Anthropic 18 of 18, the Hugging Face Hub and Mistral with only known-flaky steps failing, OpenAI 15 of 16. The OpenAI failure is gpt-4o's intermittent long-answer slip (it wrote `<functions.write_note …>` as text), 2 of 28 attempts since the output entry stopped being tag-shaped; the step is now in `KNOWN_FLAKY` with that rate. Gemini was skipped: its key is over its monthly spending cap.
- **Live robot gate in tool mode** (`WICA_ROBOT_OUTPUT=tool`), one run per provider, locally: Anthropic 15 of 15; the Hugging Face Hub with one known-flaky step failing; Mistral with every step passing, the six on its known-flaky list included; OpenAI 14 of 15. The OpenAI failure came in the robot's setup: still issuing Commands 30 s after the person walked up (`c11`), the chained wakes this mode had before. The cap bounds wakes from the Agent's own output only, not those from other Commands.
- **Live coverage by output mode**, the two tool-mode configs three runs each (18 tests a run), locally: Mistral 52 of 54, its two failures on `long_answer` (no `write_note` within 60 s once, still speaking 30 s after the note once); the Hub's tool config 52 of 54, its two failures on `background` (a `say` call instead of `noop`, as its tag config does). Each is a `KNOWN_FLAKY` entry with that rate; nothing else failed.
