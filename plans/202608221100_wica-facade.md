# WICA facade + lifecycle refactor

**Status:** Done

Implements [specs/wica.md](../specs/wica.md) (new, Stable) and the four spec updates it forces:
[world.md](../specs/world.md) (drop singleton; add `start`/`stop`/`is_running`; take the shared loop
at construction and dispatch on it; replace `set_trigger_handler` with an `on_trigger` Event),
[agent.md](../specs/agent.md) (`Agent` constructed from `AgentConfig`, `from_config` removed; run on
the injected loop, no owned thread, no trigger bridge; instrumentation hooks become `on_trigger`/
`on_prompt`/`on_command` Events, and the Agent subscribes to the World's `on_trigger`),
[events.md](../specs/events.md) (subscriber-isolating `emit`), and [config.md](../specs/config.md)
(flow now runs through `Wica.init`). All four are currently **Updated** — this plan brings the code
back to matching them and returns them to **Implemented**, and promotes `wica.md` to **Implemented**.

The same code changes also reach into **four downstream specs** whose `Implemented` text the reshape
invalidates — [inputs.md](../specs/inputs.md) (World's threading model, governs `world.py`),
[testing.md](../specs/testing.md) (per-test `World` isolation replaces `reset_world`; governs the
conftests + e2e support), [conversation-demo.md](../specs/conversation-demo.md) (demo now built via
`Wica.init`), and [fake-provider.md](../specs/fake-provider.md) (construction chain, governs
`agent.py`). Their bodies have already been aligned to the target design and set to **Updated**; this
plan carries the matching code and returns them to **Implemented** alongside the four above.

This is a wide change (new module + four modules edited + demo + tests + consumer docs), so the
steps are ordered bottom-up: leaf primitives first, then World, then Agent, then the `Wica` facade
that composes them, then consumers (demo, e2e) and the docs that describe the shipping API
(`INTEGRATING.md`, `README.md`, the AGENTS.md map).

## Goal

One entry point: `Wica.init(config)` **owns a single event loop** and a `World` + `Agent` that both
run on it, drives their shared `start`/`stop` lifecycle, and **surfaces four `Event`s**
(`on_world_trigger` = the World's raw trigger, `on_agent_trigger`/`on_agent_prompt`/`on_agent_command`
= the Agent's). Two structural simplifications: (1) the shared loop — the World stops owning a
`ThreadPoolExecutor` and the Agent stops owning its loop thread + the `run_coroutine_threadsafe`
bridge (one loop, one owner, symmetric injection into both); (2) signals become `Event`s — the
World's `set_trigger_handler` becomes an `on_trigger` Event the Agent subscribes to, and the Agent's
hook callbacks become `Event`s it emits, so `Wica` surfaces objects rather than adapting callbacks.
Drop the World singleton (`get_world`/`reset_world`) and the `Agent.from_config` classmethod. No
behavior change to the reasoning loop, rendering, coalescing, or Command execution — this is an
API/lifecycle/dispatch reshape; listener dispatch additionally gains sync/async handling with
per-callback isolation.

## Steps

### 1. `events.py` — subscriber-isolating `emit` ([events.md](../specs/events.md))

- In `Event.emit`, wrap each handler call in `try/except Exception`, logging the exception via a
  module logger (`_logger = logging.getLogger(__name__)`) and continuing to the next handler, so
  one raising subscriber can't starve its siblings. Keep iterating the *snapshot* copy of the
  handler list (unchanged).
- `import logging` is the only new import — `events.py` stays a pure stdlib leaf (no project
  imports), so it remains copyable into another project unchanged.
- Tests (`tests/test_events.py`): add a case with two subscribers where the first raises and assert
  the second still fires; assert `emit` does **not** propagate. Update/remove the existing test that
  pins the current propagate-out-of-`emit` behavior.

### 2. `world.py` — shared loop, lifecycle, drop the singleton ([world.md](../specs/world.md))

- **Remove** the module-level `_world` global, `get_world()`, and `reset_world()`.
- **Take the loop at construction:** `World(self, loop: asyncio.AbstractEventLoop)`. **Drop the
  `ThreadPoolExecutor`** entirely — the World no longer owns one; it dispatches on the injected loop
  (using the loop's own default executor for sync callbacks, below).
- Add lifecycle state `self._running: bool = False` and a read-only `is_running`.
  - `start()`: set `self._running = True`.
  - `stop()`: cancel + clear all timers (reuse `_cancel_all_timers`), set `self._running = False`.
    Idempotent-safe. Does **not** touch the loop (Wica owns it).
- **Listeners — loop-based, sync/async, guarded dispatch.** Replace the `self._executor.submit(cb,
  entry)` site for **listeners** with `self._loop.call_soon_threadsafe(self._dispatch, cb, entry)`,
  where `_dispatch` runs on the loop and branches:
  - `asyncio.iscoroutinefunction(cb)` → `self._loop.create_task(self._run_guarded_async(cb, entry))`
    (a wrapper coroutine that `try/except`-logs).
  - else → `fut = self._loop.run_in_executor(None, cb, entry)` then
    `fut.add_done_callback(self._log_if_failed)` (retrieve + log any exception; never re-raise).
  - This makes a blocking sync listener run on a worker thread (non-blocking to the loop), runs
    listeners in parallel/concurrently, and isolates a throwing one — closing the old silent-failure
    gap. `add_listener` accepts a **sync or async** callback (broaden the type to
    `Callable[[WorldEntry], None | Awaitable[None]]`).
- **Trigger — replace `set_trigger_handler` with an `on_trigger` Event.** Add
  `self.on_trigger: Event[WorldEntry] = Event()` (from `wica.events`). **Remove** `set_trigger_handler`
  and the `_trigger_handler` slot. In `_update`, where an update qualifies (`triggers_llm_call` +
  `trigger_condition_fn`), replace the old trigger-handler `submit` with
  `self._loop.call_soon_threadsafe(self.on_trigger.emit, entry)` — emitting on the loop thread so a
  subscriber may safely `create_task`. The qualifying logic is unchanged; only the delivery mechanism
  changes. `update()` stays callable from any thread (it only schedules via `call_soon_threadsafe`).
- **Guard only the reactive path:** `update()`/`_update` raise `RuntimeError("World is not running")`
  when `not self._running`. Leave `register`, `unregister`, `get`, `get_entry`, `get_prompt_entries`,
  `add_listener`, `remove_listener`, subscribing to `on_trigger`, `render_*` **unguarded** (they need
  no running loop), so setup-before-`start` and reads-after-`stop` keep working. (TTL `_ttl_expire`
  calls `_update` but only from a live timer, which `stop()` cancels — so it can't hit the guard
  after stop. TTL timers stay `threading.Timer`; a reset routes its trigger/listeners through the
  loop like any update.)
- Tests (`tests/test_world.py`): replace `get_world()`/`reset_world()` with a fixture giving each test
  a `World(loop)` on a loop running in a thread + `start()`/`stop()`. Add: `update` before `start` /
  after `stop` raises; `register`/`get` work while stopped; a **sync** listener that blocks does not
  stall other dispatch; an **async** listener runs; a listener that raises is isolated (siblings still
  fire, no propagation); an `on_trigger` subscriber receives the qualifying entry (and a
  `trigger_condition_fn` that fails suppresses the emit); `register`/`get` after stop still readable.

### 3. `agent.py` — construct from `AgentConfig`, run on the injected loop ([agent.md](../specs/agent.md))

- Change `Agent.__init__` to take `config: AgentConfig` as its first positional argument instead of a
  built `model`. Inside `__init__`, resolve and build: `system_prompt = resolve_system_prompt(config)`
  and `model = build_chat_model(config)`. Keep the keyword args `output_sink`, `coalesce_window`.
- **Remove** the `Agent.from_config` classmethod (its body moves into `__init__`).
- **Instrumentation hooks → Events.** Add `CommandIssued` (frozen dataclass `name: str`,
  `args: dict[str, Any]`) to `agent.py`. Create Events in `__init__`:
  `self.on_trigger: Event[WorldEntry] = Event()`, `self.on_prompt: Event[list[BaseMessage]] = Event()`,
  `self.on_command: Event[CommandIssued] = Event()`. **Drop** the `on_prompt`/`on_trigger`/`on_command`
  constructor params and the `_fire_hook` helper. At the existing hook sites, emit instead:
  `self.on_prompt.emit(messages)`; per collected trigger in `_run_step`, `self.on_trigger.emit(entry)`;
  at command dispatch, `self.on_command.emit(CommandIssued(name, args))`. `Event.emit`'s isolation
  replaces `_fire_hook`'s guard. (Agent `on_trigger` is the **filtered** signal — emitted only for
  triggers a step processes; distinct from the World's raw `on_trigger` below.)
- **Loop is injected, not owned.** `world` and `loop` become **required** keywords (no `get_world()`
  fallback, no self-created loop). **Remove** the loop-owning machinery: `self._owns_loop`,
  `self._loop_thread`, creating `new_event_loop()`, starting/stopping/joining the thread in
  `start()`/`stop()`. The Agent uses `self._loop = loop` for its tasks, timers, and cancellation, but
  never starts or stops it — `Wica` owns the loop thread.
- **Subscribe to the World's trigger — no bridge.** Remove `_on_world_trigger` and its
  `run_coroutine_threadsafe(...)`. In `start()`, subscribe the async-scheduling shim
  `self._trigger_sub = lambda e: self._loop.create_task(self._handle_trigger(e))` via
  `self._world.on_trigger.subscribe(self._trigger_sub)` (the World emits `on_trigger` on the loop
  thread — see step 2 — so `create_task` is safe). `start()` still auto-registers `cancel_command`.
- `stop()`: `self._world.on_trigger.unsubscribe(self._trigger_sub)`, cancel the pending
  coalescing-window timer, and cancel in-flight Command tasks (as today) — but no loop teardown.
- `build_chat_model` stays a module-level function in `agent.py`.
- Tests (`tests/test_agent.py`, `tests-e2e/test_agent.py`): construct via
  `Agent(config.agent, world=w, loop=loop, …)` against a `World(loop)` on a running loop (a shared
  fixture with step 2's World fixture). The deterministic-model seam is
  `Agent(AgentConfig(provider="fake", …), world=w, loop=loop)`.

### 4. `wica.py` — the facade (new module), owns the loop ([wica.md](../specs/wica.md))

- New `src/wica/wica.py` with the `Wica` class (`CommandIssued` lives in `agent.py` — step 3 — and
  is imported/re-exported here):
  - `Wica.init(config, *, output_sink=None, coalesce_window=0.2, loop=None)` classmethod:
    **own the loop** — if `loop is None`, `self._loop = asyncio.new_event_loop()` and create the
    daemon `threading.Thread(target=self._loop.run_forever, daemon=True)` (set `_owns_loop=True`);
    else adopt the injected loop (`_owns_loop=False`, no thread). Then build `World(self._loop)` and
    `Agent(config.agent, world=self.world, loop=self._loop, output_sink=…, coalesce_window=…)`; call
    `apply_logging(config.logging)`; store `self.world`, `self.agent`; return the instance.
  - **Surface the Events** (no adapters, no `emit` shims — hold the same objects):
    `self.on_world_trigger = self.world.on_trigger`, `self.on_agent_trigger = self.agent.on_trigger`,
    `self.on_agent_prompt = self.agent.on_prompt`, `self.on_agent_command = self.agent.on_command`.
  - `wica.world`, `wica.agent` — plain public attributes.
  - `start()` → start the loop thread (if `_owns_loop`), then `world.start()`, then `agent.start()`.
  - `stop()` → `agent.stop()`, then `world.stop()`, then (if `_owns_loop`)
    `self._loop.call_soon_threadsafe(self._loop.stop)`, join the thread, and `self._loop.close()`
    (closing shuts the loop's default executor used for sync listeners).
  - `register_command(fn, *, name=None, description=None)` → delegates to `agent.register_command`.
- Tests: new `tests/test_wica.py` — `init` wires world+agent (sharing one loop) and applies logging;
  the four surfaced Events are the *same objects* as `world.on_trigger`/`agent.on_trigger`/
  `agent.on_prompt`/`agent.on_command`; `start`/`stop` order (agent stopped before world — a
  cancelled-command update during stop must not raise; the loop thread stops last); an input drives
  `on_world_trigger` then `on_agent_trigger` and `on_agent_command` emits a `CommandIssued`; multiple
  subscribers on one Event all fire and a raising one doesn't block the others (end-to-end);
  `register_command` reaches the agent; after `stop()`, `wica.world.update(...)` raises
  `RuntimeError("World is not running")`.

### 5. `__init__.py` — public surface

- Add `Wica` (from `wica.wica`) and `CommandIssued` (from `wica.agent`). **Remove** `get_world` (and
  don't add `reset_world`). Keep `World`, `WorldEntry`, `Event`, config exports, etc. Update `__all__`.

### 6. Consumers: demo + fake-flow e2e

- `examples/conversation_demo.py`: replace `get_world()` + `Agent.from_config` + manual `apply_logging`
  + three loose callbacks with `Wica.init(config, output_sink=…)`, then `wica.world.register(...)` for
  the entries, `wica.register_command(...)` for the commands, and `.subscribe(...)` on the Events for
  the panels: `wica.on_agent_prompt` (prompt panel), `wica.on_agent_trigger` (input side — matches
  today's filtered behavior), `wica.on_agent_command` (assistant side). Commands that close over the world now close
  over `wica.world`. `main()`'s `finally` calls `wica.stop()`. The MissingEnvError degrade-to-explore
  path moves to wrap `Wica.init`.
- `tests-e2e/test_fake_flows.py`: `test_scripted_flow_through_config_path` goes through `Wica.init`
  (the real entrypoint); `test_scripted_flow_direct_construction` uses `Agent(AgentConfig(provider=
  "fake", …), world=…)`. Both construct their own `World()` with `start()`/`stop()` (or via `Wica`).
- `tests/conftest.py` + `tests-e2e/conftest.py`: **remove** the `reset_world()` autouse fixture (no
  singleton to reset). Test isolation is now a fresh `World(loop)` per test — provide the shared
  loop-plus-`World` fixture (step 2) that `test_world.py`/`test_agent.py` build on. This matches
  [testing.md](../specs/testing.md)'s rewritten "Test isolation" section.
- `tests-e2e/support.py`: `real_agent()` constructs `Agent(config.agent, world=…, loop=…)` directly
