# Text output: the model speaks through tags in its text

**Status:** Done

Implements the single output path of [specs/agent.md](../specs/agent.md) ("Output: tags in the model's text", "Continuing after an output", "Output wiring", "The agent may choose not to act", "Response guards") and [specs/commands.md](../specs/commands.md) ("The output Command — what the model says to its user", "Doing nothing is not a Command"), and what follows from it in [wica.md](../specs/wica.md), [config.md](../specs/config.md), [instrumentation.md](../specs/instrumentation.md), [wica-tester.md](../specs/wica-tester.md), [testing.md](../specs/testing.md), [fake-provider.md](../specs/fake-provider.md), [gradio-contrib.md](../specs/gradio-contrib.md), [conversation-demo.md](../specs/conversation-demo.md) and [benchmark.md](../specs/benchmark.md).

**Why.** Speech as a forced tool call delays the first word, depends on `tool_choice` (ignored by some self-hosted servers), costs a second model call per utterance and feeds runaway chains; free text to a sink has no lifecycle, cannot be cancelled and carries no parameters. A tag in the text keeps the benefits of both. Measurements and the alternatives rejected: `analysis/_text-output.md` (local notes).

**This is a breaking change and the only path**: the output sink, the forced tool call, its guard and the `noop` tool are removed, not deprecated.

## Scope

### 1. The parser — `src/wica/text_output.py` (new, LangChain-free)

- `OutputStream`: async iterator of text pieces, `text`, `heard`, `read()`. Exported from `wica`.
- `TextOutputParser(name | None, on_open, on_delta, on_close)`: incremental; `feed(delta)`, `finish() -> ParseResult` (`raw`, `outputs`, `private`, `note`, `noop`, `segments` for the history cut). One output per tag; the lenient rules; with `name=None` (no output Command) all text is private and only `<noop/>` is recognised.
- `output_signature(command) -> (streams: bool, attributes: {name: allowed values | None})`, raising `ValueError` for a signature that cannot be an output's.

### 2. The Agent — `src/wica/agent.py`

- Remove: the `noop` Command and `NoReactionRecord`; `set_output_sink` and the sink call; `_bind_tools_forced` and `force_tool_call`; `_TRIGGER_ON_OUTPUT_COMMAND_COMPLETION`; `on_text`.
- `set_output_command`: validation by signature; the output Command is not attached to the model binding; `commands` no longer lists it.
- The step: feed text deltas to the parser while the call streams; open an output at its first words (entry, task, `first_output_at`); settle the response synchronously when it ends (history record, `on_command` per output, the `<next>` note, the wake of the last output); guards run only for a response that started no output.
- Outputs: sequential within a response, one voice across responses, final state held until the issuing step is over, the history cut from `OutputStream.heard`.
- `<next>`: the `agent:next` entry, shown once; `max_next_steps`; `output_wakes(call_id)`.
- The primer: the five parts, their wording taken from the measured prototype, the continuation example neutral.
- Events: `on_private_text`; `on_command` for an output at the end of its body; nothing for `<noop/>`.

### 3. Around the Agent

- `guards.py`: drop `output_command_required` and `ModelResponse.output_command_name`; `incomplete_response` no longer has the "before the call an output Command requires" case.
- `config.py`: drop `force_tool_call`; add `max_next_steps` (`int | None`, default `1`, `>= 0`).
- `instrumentation.py`: `ReactionTrace` loses `sink_duration`, gains `first_output_at`; the `wica.agent.sink` span goes.
- `wica.py`, `__init__.py`: drop `set_output_sink` and `on_agent_text`; add `on_agent_private_text`; export `OutputStream`.
- `fake_model.py`: nothing structural (a script step's `text` carries the tags); its documentation and defaults.

### 4. Tooling

- `wica.testing`: the Probe's events (`private_text`; `noop` read from the reaction record); idle detection through `Agent.output_wakes`; the checks (`cancels_when_asked` also passes on an output cut off; `no_noop_on_input`, `quiet_on_background_change`, `answers_each_input`, the measures); the tester's default response becomes the text `<noop/>`.
- `wica.contrib.gradio`: the transcript and the reaction history without a sink or a `noop` command event.
- `wica.benchmark`: nothing structural; the summary's wording where it names `noop`.

### 5. Applications and tests

- `examples/conversation_demo`: `say(text: OutputStream, …)`, the persona, the panels.
- `benchmarks/`: `DemoTarget`, the scenarios' checks, the `fake` fixture's script. Kept results stay as recorded history.
- `tests-e2e/`: the test robot (`say` as a streaming output), `test_wica.py`, the scripted-fake flows, the scenarios, `KNOWN_FLAKY` re-vetted.
- `tests/`: rewritten where they pin the removed behaviour; `tests/test_text_output.py` for the parser and the signature.

### 6. Documentation

- `docs/` (the API and configuration references first, then the guides that mention the sink, `noop`, forcing or `on_text`), `README.md` (the quick start), `AGENTS.md` (the project map row for `text_output.py`, the `agent.py` and `guards.py` rows), `CONTRIBUTING.md` if touched.

Not in scope (open points in `analysis/_text-output.md`): a Command that waits for the end of speech; tool calls written as text for local models; a cap on chains through application Commands; the dropped wake of a fast Command that ends inside its own step.

## Tests

- **Parser**: a tag streams only its body; the body starts before the response ends and a possible closing tag is held back; several tags give several outputs with their attributes; untagged text is one output at the end; `<noop/>` alone, beside an output, beside private text; an unclosed tag; other angle brackets; the note; no output Command.
- **Signature**: `OutputStream` and `str` first parameters; `Literal` and `str` attributes; a missing default, a non-string attribute and a `BaseTool` are refused.
- **Agent, scripted fake**: attributes reach the Command, a bad one falls back to the default; two tags are delivered in order; a `str` output Command is called once with the whole text; `<noop/>` sets the record's flag, issues nothing and leaves the model unbound from any `noop` tool; no note, no wake; a note wakes one step that sees it once; the cap; speaking again cuts off the running output and leaves a running Command alone; history after a cut; a short output ending before its response still wakes; a response that started an output is not retried, one that did not is; no output Command, all text private.
- **Tooling**: idle with and without a granted wake; the checks over outputs and `<noop/>`; the tester ending on `<noop/>`.
- **Live**: the gate, three runs per provider, before and after numbers recorded in the pull request.

Two follow-ups landed before the statuses: the output's World entry wording without a verb (in #26), then not tag-shaped (#27), after gpt-4o began writing its tools as tags (`<functions.write_note …>`) on `main`'s live run. Gemini was not verified: its key was over its monthly spending cap throughout.
