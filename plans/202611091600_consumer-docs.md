# Consumer documentation: README as landing page, `docs/` by task, CONTRIBUTING, docs checks

**Status:** Done

Give WICA the documentation shape its sibling repos (`tts-engine`, `reachy-mini-bridge`) converged on, so one vocabulary and one layout hold across the funwithagents repos: the README is a landing page, the consumer documentation lives under `docs/` and is entered by task, `CONTRIBUTING.md` says how the project is run, and a fast-tier test keeps the Markdown honest. Implements the `Updated` parts of [project.md](../specs/project.md) ("Repo shape": `README.md`, `CONTRIBUTING.md`, `docs/`; "Documentation checks"). Flip that spec back to `Implemented` when this plan is `Done`.

Decisions, settled in the study that preceded this plan (2026-11-09, a read of both sibling repos' `README.md`, `docs/index.md`, `CONTRIBUTING.md`, docs tests and `project.md`):

- **The README stops being the manual.** It keeps the pitch, the four pillars, a status and feedback callout, a "What WICA gives you" table (the former "Why WICA" bullets), Install with the provider extras table (the former "Providers" section), the shortest runnable quick start, the conversation demo, a Documentation table, "How it is developed" and License — the siblings' section order and headings, so a reader of one repo knows where to look in the next.
- **`INTEGRATING.md` is retired into `docs/`.** It was the de facto manual, written for a coding agent; its content is kept, page by page, and the by-task index does the routing job it did. `AGENTS.md` stays the in-repo operating manual; `docs/` is the consumer's. Two entry points, as in the siblings — not three.
- **`docs/` layout, by the reachy-mini-bridge split:** `index.md` (by task), `getting-started.md`, `reference/` (the API, the configuration), `guides/` (one page per task). One home per fact: a reference page owns it, every other page links there; the specs stay the normative design.
- **The three shipped surfaces without a consumer page get one:** `wica.testing` and the `fake` provider (guides/testing.md), `wica.benchmark` (guides/benchmarking.md), the instrumentation Events and OpenTelemetry (guides/latency-and-traces.md).
- **Docs checks follow `tts-engine`'s `tests/test_docs.py`:** every relative link and heading anchor resolves; the examples a reader copies are executed (the README quick start with a scripted model standing in for the provider it names, the getting-started application and the testing guide's examples on `provider: "fake"` as written); the tables that mirror code are checked against it (the provider extras against `pyproject.toml`, the configuration fields against `AgentConfig`, the imports against `wica.__all__`, the Events against `Wica`). The existing method-name drift guard of `tests/test_project_map.py` moves in.
