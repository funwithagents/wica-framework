# Fake provider (deterministic scripted model)

**Status:** Done

Build the `provider: "fake"` chat model specified in [fake-provider.md](../specs/fake-provider.md): a deterministic, network-free, key-less `BaseChatModel` whose every step is scripted via `model_kwargs`, selected through the same `WicaConfig → AgentConfig → build_chat_model → Agent.from_config` path production ships. It exists to write **deterministic scripted whole-flow tests** of the Agent loop, which live in the `tests-e2e/` full-loop tier as an **always-run** set (never skip — no key/network), and to let projects integrating WICA do the same in their own e2e suites.

The design's remaining open questions are genuine deferrals (reactive fake, alignment aids, a separate fast unit test of the fake's mechanics), so this plan assumes the spec is design-validated: **promote [fake-provider.md](../specs/fake-provider.md) `Draft → Stable` at the start of this work**, then `Stable → Implemented` on completion (see Step 6).

Scope notes (decided in the spec): the fake *drives the Agent loop* only in the e2e flow tests — the loop is **not** brought into the fast `tests/` tier — but the fake's own mechanics still get a fast unit test in isolation (`tests/test_fake_model.py`); the reactive/callable fake is **out** (a JSON script suffices); latency is **shipped** (`delay_s`, default 0.2 s), not deferred.

**Test placement (decided — see the analysis that led here):** the fake is deliberately kept **out** of the live-provider `PROVIDER_CONFIGS` parametrization. A fixed script is non-reactive, so one shared `fake` config cannot satisfy contradictory reactive tests — e.g. [test_agent.py](../tests-e2e/test_agent.py)'s `test_real_tool_calling_round_trip` needs a test-specific `add(2,2)` call that the same config's `test_plain_text_round_trip` must *not* emit (and would trip the fake's name-check when `add` isn't registered). Adding `fake` there would convert a currently-skipping slot into a hard failure. Instead the fake gets its **own** flow file where each test supplies its own script.

## Steps

### 1. New module: `src/wica/fake_model.py`

A public `FakeChatModel(BaseChatModel)` — LangChain models are pydantic v2, so declare the scripted config as fields and the mutable run state as `PrivateAttr`s:

```python
class FakeChatModel(BaseChatModel):
    script: list[dict[str, Any]] = Field(default_factory=list)   # ordered step responses
    default: dict[str, Any] = Field(default_factory=lambda: {"text": ""})  # returned once script is spent
    loop: bool = False              # cycle the script instead of falling to `default`
    delay_s: float = 0.2            # awaited before each response (200 ms) — see spec "Simulated latency"

    _cursor: int = PrivateAttr(default=0)
    _calls: list[list[BaseMessage]] = PrivateAttr(default_factory=list)  # messages seen per call
    _tool_names: set[str] | None = PrivateAttr(default=None)  # last bind_tools' names, for validation
    _validated: bool = PrivateAttr(default=False)
```

- **`_llm_type`** → a constant like `"wica-fake"`.
- **Response building** (shared by sync/async): a step `{"text": str?, "tool_calls": [{"name", "args"}]?}` → an `AIMessage(content=text, tool_calls=[...])`. Each tool call becomes a native LangChain `ToolCall` dict `{"name", "args", "id", "type": "tool_call"}`, with a **deterministic** generated `id` when none is supplied (e.g. `f"fake_call_{step_index}_{i}"`) so flow-test assertions stay reproducible. Wrap in `ChatResult(generations=[ChatGeneration(message=...)])`.
- **Queue semantics**: each generate consumes `script[cursor]` and advances; once `cursor` runs past the end, return `default` — unless `loop` is set and the script is non-empty, in which case return `script[cursor % len]`. Record every received message list into `_calls`.
- **`_agenerate`** is the real path (the Agent only ever calls `ainvoke` → [agent.py:435](../src/wica/agent.py#L435)): record the call, run validation (below), `await asyncio.sleep(self.delay_s)` when `delay_s`, then return the built result. Because the sleep is a genuine `await`, a `task.cancel()` landing during it unwinds cleanly. Also implement the abstract **`_generate`** (sync sibling, no sleep, shares the builder) so the class is concrete.
- **`bind_tools(tools, **kwargs)`**: record `self._tool_names = {t.name for t in <normalized tools>}` and **return `self`** (the canned output is unaffected; a real `RunnableBinding` isn't needed — returning the model keeps `ainvoke` working).
- **Name validation is lazy — at first generate, not at bind time.** The Agent calls `bind_tools` **once per `register_command`**, each time with the *full current* command list, and auto-registers `cancel_command` inside `start()` ([agent.py:280](../src/wica/agent.py#L280), [:288](../src/wica/agent.py#L288)). Validating inside `bind_tools` would therefore fire against a *partial* tool set and wrongly reject a script that names a not-yet-registered command. So instead validate **once, on the first `_generate`/`_agenerate`**, against the most-recently-bound `_tool_names`: assert every scripted `tool_calls[].name` is in it, else raise a clear `ValueError` naming the offending command and the known tools. (This realizes the spec's "`bind_tools` validates" intent robustly; fold a one-line clarification of *when* validation fires back into the spec's "`bind_tools` & name checking" section in this same change.)
- Expose read-only **`calls`** (property over `_calls`) for prompt assertions.

No network import, no provider extra — the module depends only on `langchain_core`, already a core dependency.

### 2. Construction branch in `build_chat_model` ([agent.py](../src/wica/agent.py))

Add a `provider == "fake"` branch to [build_chat_model](../src/wica/agent.py#L165), before the `huggingface-hub` branch and the `init_chat_model` fallthrough:

```python
if config.provider == "fake":
    from wica.fake_model import FakeChatModel
    return FakeChatModel(**config.model_kwargs)   # script/default/loop/delay_s live in model_kwargs
```

- For the fake, `model_kwargs` **is** the fake's construction payload (script/default/loop/delay_s), not provider kwargs — this is exactly what keeps it JSON-expressible and on the ordinary config path. Unknown keys in `model_kwargs` surface as a pydantic error at construction (a small bonus of strictness).
- `api_key`/`api_key_env` need no handling: config already resolves to `api_key=None` when absent, and this branch simply ignores any key. `config.model` is a free-text label, unused.
- Define the provider string as a module constant next to `_HUGGINGFACE_HUB_PROVIDER` for symmetry (e.g. `_FAKE_PROVIDER = "fake"`).

### 3. Public API + project map

- **Keep the module public, but do not re-export it from the top-level `wica` namespace.** `FakeChatModel` is a **test double**, not runtime API — the top-level `wica` surface (`World`/`Agent`/`Content`/config) stays runtime-only. Integrating projects import it explicitly as `from wica.fake_model import FakeChatModel`, which its public (non-`_`-prefixed) module name already allows; the submodule path itself signals "test tooling." So [`src/wica/__init__.py`](../src/wica/__init__.py) and `__all__` are **left untouched** — no re-export, no public-API-table reshuffle. (The primary use case, `provider: "fake"` via config, imports nothing anyway; the export would only ever alias the direct-construction path.)
- Add a **project-map row** for `fake_model.py` to the `src/wica/` module table in [AGENTS.md](../AGENTS.md), spec column → [fake-provider.md](../specs/fake-provider.md). Required by `tests/test_project_map.py::test_agents_md_maps_exactly_the_wica_modules` and `test_every_concept_module_is_governed_by_a_spec` — this holds regardless of the `__init__.py` re-export.
- Once the module and **both** test files exist, the currently-red `test_spec_frontmatter_paths_all_exist` (the spec's frontmatter names `tests/test_fake_model.py` and `tests-e2e/test_fake_flows.py`) goes green — no frontmatter edit needed.

### 4. Tests

Two homes, mirroring the spec's "Two test homes" split — the component's mechanics in the fast tier, its wiring into the whole loop in the e2e tier.

#### 4a. Fast unit tests: `tests/test_fake_model.py`

Drive `FakeChatModel` **directly** (no Agent, no network), so these run in the default `uv run pytest`. Functional assertions on the implementation itself:

- **Script consumption order** — successive `ainvoke`/`invoke` return `script[0]`, `script[1]`, … as distinct `AIMessage`s.
- **Text / tool-call mapping** — a `{"text": …}` step → `AIMessage.content`; a `{"tool_calls": [...]}` step → native `AIMessage.tool_calls` with `name`/`args`; a supplied `id` is preserved, an absent one gets the **deterministic** generated id (assert the exact value so the determinism is pinned, not just non-empty).
- **Exhaustion** — once the script is spent, further calls return `default`; with `loop: true`, they **cycle** the script instead.
- **`delay_s`** — defaults to `0.2`; passing `0` returns promptly. Cancellation: start `ainvoke` as a task with a non-trivial `delay_s`, cancel it mid-sleep, assert `CancelledError` propagates (the "real `await` ⇒ cancellable" guarantee, tested without the full loop).
- **`bind_tools` name-check** — validation is **lazy** (fires on first generate, not at bind): a script naming a tool that *is* among the bound names invokes fine; one naming an unknown tool raises a clear `ValueError`; and a `bind_tools` call with a partial set followed by a fuller one (mimicking the Agent's per-command rebinds) does **not** wrongly reject.
- **`.calls`** — records the message lists it was handed, in order.

#### 4b. Scripted-flow tests: `tests-e2e/test_fake_flows.py`

A new **always-run** file in `tests-e2e/` (uncollected by the default `uv run pytest` since `testpaths = ["tests"]`; the autouse `reset_world` fixture in [tests-e2e/conftest.py](../tests-e2e/conftest.py) gives World isolation). It is **outside** `PROVIDER_CONFIGS`, so it neither parametrizes over providers nor skips on a missing key. **Filename chosen so `-k fake` selects it** (see the `-k` note below).

- **Drive the loop through the config path** — the point of the provider value. Build via `WicaConfig.from_dict({...})` with `provider: "fake"`, an inline `system_prompt`, and `model_kwargs` carrying the `script`, then `Agent.from_config(cfg.agent, world=..., output_sink=...)`. (A second, lighter test may construct `FakeChatModel(...)` directly and pass it to `Agent(model=...)` to cover that seam.)
- **A multi-step flow, asserted exactly.** Register a trivial async Command (e.g. `add`, mirroring [tests-e2e/test_agent.py](../tests-e2e/test_agent.py)), register an Input entry, `update()` it to trigger, and script the model to (step 1) call the command and (step 2) speak a line. Assert deterministically:
  - the command's `agent:command:<call_id>` entry goes terminal with the expected `result` (listen on the key, per the existing test's race note),
  - the output sink received the scripted text,
  - `model.calls[k]` shows the expected prompt at a given step (e.g. the earlier command's result rendered as an observation on the later step) — the `.calls` introspection the spec calls out.
  - **Script for the re-trigger steps.** A completed Command re-triggers the loop, so more `ainvoke`s occur than there are "intentional" model turns; rely on `default: {"text": ""}` to absorb the trailing steps (this is the "alignment" open question in practice — the test controls the trigger sequence, so a fixed script aligns).
- Most flow tests can pass `delay_s: 0` in `model_kwargs` to stay fast; the default-`0.2`/cancellation behavior is already covered by the unit test in 4a.

#### `-k` ergonomics

`-k EXPR` substring-matches against each test's name, its **parents (module filename, class)**, and parametrization ids. Because the flow file is named `test_fake_flows.py`, the `-k` story stays symmetric with the live providers even though the fake isn't a `PROVIDER_CONFIGS` entry:

| Command | Runs |
|---|---|
| `pytest tests-e2e -k anthropic` (or `openai`/`huggingface`) | that live provider's param cases only; fake flows **excluded** (no substring match) |
| `pytest tests-e2e -k fake` | the whole `test_fake_flows.py` module — **always-run, no skips**, a fully offline green signal |
| `pytest tests-e2e` | everything: live providers skip-or-run per key, fake flows always run |

## Notes / out of scope

- **Reactive/callable fake** — out (spec OQ#1). A JSON script covers whole rounds when the test controls the trigger sequence; a `messages -> response` callable would need a non-JSON seam and is deferred until a script proves insufficient.
- **No new provider extra / packaging change** — the fake depends only on `langchain_core`, so `pyproject.toml` is untouched (unlike the multi-provider plan). Core `wica` gains `provider: "fake"` with no optional install.
- **`bind_tools` returns `self`, not a real binding** — acceptable because the fake's output is canned; the only thing binding does here is record tool names for the lazy name check.
